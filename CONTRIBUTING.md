# Contributing to KIN Seed

KIN Seed currently accepts contributions to the open specification, schemas, conformance vectors, threat model, training design and evaluation plan.

Do not submit a generated participant implementation. Local node code is intentionally private and disposable. Instead, submit behavioural evidence: protocol messages with synthetic data, conformance results, implementation fingerprints, failure reports and proposed specification changes.

## Contribution requirements

- Do not include personal or confidential data.
- Do not include credentials, signing keys or payment addresses.
- Do not include generated node source code or executables.
- State which protocol version the evidence concerns.
- Distinguish observed results from proposals.
- Include a reproducible synthetic test when changing protocol behaviour.
- Agree that specification contributions are licensed under Apache License 2.0.

Security vulnerabilities should follow `SECURITY.md` rather than a public issue.
